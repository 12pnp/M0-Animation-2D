Two changes asked together: the Reference panel should sit **against the Timeline tab** (today it is a right-dock panel stacked under Preview), and **each reference picture's frame number must be shown and editable** — today the badge on each thumbnail is only *computed* from "Starts at" + "Each image × frames", so pictures can only be evenly spaced. Goal: pictures can sit at arbitrary frames (1, 5, 12, 30…), which is what real rotoscope/reference runs look like.

## 1. Reference docks beside the Timeline tab

Arrangement: Reference becomes a **sibling tab of Timeline in the bottom dock** — the tab strip at the bottom reads `Timeline | Reference`. (If you'd rather have it as its own section under the Timeline, say so; that is a one-token change in the default below.)

**`src/app/App.ts`**
- `registerPanels()` (line ~249): the ReferencePanel moves from `shell.addRightPanel(…)` to `shell.addBottomPanel(…)`. The `panelDock` map updates itself, so Window ▸ Reference, Float/Dock Reference and `showPanel` keep working unchanged.
- Default layout (line ~158): right dock becomes `[["properties"], ["library", "outline"], ["preview"]]`, bottom dock `[["timeline", "reference"]]`.

**`src/view/widgets/Dock.ts` — the one wrinkle: stored layouts.** Layouts persist in `localStorage` (`animo.dock.right` / `animo.dock.bottom`). `prune()` currently appends a never-placed panel as a *new singleton group*, so an existing install (yours included) would get Reference as a group *below* Timeline instead of a tab beside it. Fix `prune()` generically: a panel that exists nowhere goes **into the group that holds its default group-mate** (setDefault remembers the default groups) — Reference lands right after Timeline in its group — falling back to a new singleton group only when there is no such group. No storage-version bump, and any future panel move gets the same treatment.
- Known consequence, accepted: if Reference was closed or floating in the old right dock, it comes back docked beside Timeline (closed/floating state does not transfer docks).

## 2. Per-image frame numbers, editable

**Model — `AnimationReference` (`src/core/doc/types.ts`)**
- Add `at: number[]`, same length as `frames`: `at[i]` is the frame picture *i* is keyed to. This becomes the **source of truth** for timing.
- `start`/`hold` stay as *bulk-spacing inputs*: the panel's "Starts at" and "Each image N frames" fields recompute the whole `at` array (`start + i×hold`), and the sheet dialog seeds it. `ReferenceService.add()` materializes `at` for new references.
- Showing rule: picture *i* shows from `at[i]` **until `at[i+1]`** (uneven gaps hold the previous picture — what you want while animating against poses); the last picture holds `hold` frames, so `referenceEnd = at[last] + hold − 1` — identical to today when spacing is even.

**Helpers — `src/core/doc/reference.ts`**
- `referenceFrameOf(ref, i)` → `ref.at?.[i] ?? ref.start + i×ref.hold` (fallback keeps half-migrated payloads readable).
- `referenceIndexAt(ref, frame)` → the last index in strip order with `at[i] ≤ frame`, null before the first or past the end. Linear scan; strips are dozens of pictures at most.
- `referenceEnd(ref)` → `at[last] + hold − 1` (fallback formula when `at` is absent).

**Migration 10 → 11 — `src/core/doc/schema.ts`, `DOC_VERSION` in `types.ts`**
- Every animation with a reference lacking `at` gets `at = frames.map((_, i) => start + i×hold)`. Additive, but the version must move: an older build would drop `at` on save and silently re-space the pictures evenly.
- The schema reader sanitizes `at`: whole numbers ≥ 0; length mismatch → regenerate from `start`/`hold`.

**UI — `src/view/panels/ReferencePanel.ts`, `src/styles/panels.css`**
- Each thumbnail's number badge becomes a compact **NumberField**: committing sets `at[i]` (rounded, ≥ 0) via `refs.update({ at: … })` — one undo step, "Set Reference Frame". Clicking the picture itself still jumps the playhead; the tooltip shows the picture's real frame range.
- The two bulk fields keep their meaning (re-space everything).
- Hint line under the strip updated: click a picture to go to its frame, type a number to move it.

**AI — `src/app/agent/AgentApi.ts` (`get_reference`)**
- `keyFrames` already maps `referenceFrameOf` — now per-picture automatically.
- The `timing` sentence (hardcoded `start + (n−1)*hold` formula, line ~317) is rewritten to the `at`/hold-until-next wording. The animation summary (line ~154) reports `[at[0], referenceEnd]`.

The stage draw (`src/view/viewport/reference.ts`) and the preview go through `referenceIndexAt` — no changes needed.
