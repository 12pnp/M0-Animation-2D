Ask AI currently runs only Claude: `mcp/amino-bridge.mjs` speaks the Anthropic Messages format end-to-end (`ANTHROPIC_API_KEY`, `x-api-key` header, `tool_use`/`tool_result` blocks). GLM (Z.ai) exposes an OpenAI-compatible chat-completions API instead. Plan: add a provider switch to the bridge with an OpenAI adapter, keeping the existing design invariant — keys live only in the bridge process env, never in the page.

## New configuration (env vars, as today)

- `AMINO_PROVIDER=anthropic|glm` — default: `glm` when `GLM_API_KEY` is set, else `anthropic`
- `GLM_API_KEY` (alias `Z_AI_API_KEY`) — key for the glm provider
- `AMINO_MODEL` — default per provider: `claude-sonnet-5-5` / `glm-4.6`
- `AMINO_API_URL` — default per provider: `https://api.anthropic.com/v1/messages` / `https://api.z.ai/api/paas/v4/chat/completions`

So GLM works with zero extra flags: `GLM_API_KEY=… node mcp/amino-bridge.mjs --http-only`.
